## 1. Context

The Policy→Action cleanup exposed the recurring failure mode of this stack: **specs amend specs amend specs.** The LEG surface went `amendment → addendum-that-restructured-it → addendum-became-normative → reconciliation-to-v1.6-numbering`. Each layer is a new drift surface, and reconciling them after the fact is expensive and error-prone.

v1.6 is declared a **soft reboot**: a single, tested, coherent baseline that the three legs work fresh from. This ADR defines the discipline that keeps it clean — so the reboot is a one-time reset, not a recurring chore.

## 2. Decision

### 2.1 Liveness marker (machine-checkable)

Every normative artifact (spec, ADR, registry, generated export, runtime contract) carries a `STATUS:` line in its header:

```
STATUS: <state> [@ <baseline>] [superseded-by: <path>] [anchored: <ref>]
```

| State | Meaning | Drift-audited? | Editable? |
|---|---|---|---|
| `live` | Current and authoritative for `<baseline>` | **Yes** | Yes (bump version in place) |
| `superseded` | Replaced; MUST carry `superseded-by: <path>` | No | No |
| `archived` | Moved to `archive/`; history only | No | No |
| `frozen` | Immutable / cryptographically anchored (e.g. `rfc/RFC-000*`, prior-version packages) | No | **Never** |

`<baseline>` is the version the artifact is current for, written as `arrow-v1.6.0`. **All three repos homologate to the Arrow baseline** — Arrow defines the version line; Tarquin and Contract Labs mark their live artifacts `live @ arrow-v1.6.0` rather than inventing parallel version numbers.

### 2.2 Numbered rules

| Rule | Statement |
|---|---|
| **LIVE-001** | Every normative artifact MUST carry a `STATUS:` line. An artifact with no `STATUS:` is treated as `live` and flagged by the next audit until marked. |
| **FLAT-001** | A live spec is **replaced, never amended by a second document.** To change a live spec, edit it and bump its version. Publishing an "amendment" / "addendum" that a reader must compose with the original is prohibited — this is the documented root cause of the v1.5→v1.6 drift. |
| **ARC-001** | Superseded artifacts move to `<repo>/archive/` in **one operation**: set `STATUS: archived`, repoint references to the live replacement, stop tracking. Archived material is not scanned by coherence/drift audits and is not retrieved except on explicit prompt. |
| **FRZ-001** | `frozen` artifacts (anchored RFCs, prior-version packages) are never edited or migrated — terminology and numbering are correct *as of their era*. Audits skip them. |
| **BASE-001** | Cross-repo prose cites the Arrow baseline (`arrow-v1.6.0`), not a private version, so "live vs not" is mechanical. |

### 2.3 Enforcement via the Dynamic Workflow suite

- **W6** (coherence audit) reads `STATUS:` to scope its disjoint-source reads to `live` artifacts only.
- **W1** (semantic-drift sweep) and **W7** (MCD simplification) skip `archived`/`frozen` paths (already encoded as `PROTECTED_PATHS`).
- A future lint (extend Arrow `tools/validate-registries.js` and Contract Labs `tools/validate.mjs`) asserts LIVE-001 and that every `superseded` carries a resolvable `superseded-by`.

## 4. Rollout sequence

1. Finish RFC-006 / RFC-007 + on-chain tests → tested 1.6 baseline.
2. Run **W6** + **W7** stack-wide; fix what they surface.
3. Apply this manifest (ARC-001) + the deferred items; add `STATUS:` lines stack-wide (LIVE-001).
4. Tag/snapshot **v1.6.0** in all three repos.
5. Restart from the flattened baseline + [ADR-0003](ADR-0003-interface-pinning-v1.md) pins, with the DW audits as CI gates.

## 5. Consequences

- **Positive:** "live vs dead" becomes mechanical; the amend-on-amend chain is banned at the source; audits get cheaper (smaller live surface); the reboot is a clean reset, not a perpetual reconciliation.
- **Cost:** a one-time `STATUS:` annotation pass and the archive move. Flattening means larger single-document edits instead of small amendments — accepted, because composing-amendments-in-your-head was the actual defect.
